# Languages

*[Polski](../pl/i18n.md) · [Français](../fr/i18n.md) · [Deutsch](../de/i18n.md)*

How Squirrel! speaks English, Polish, French and German, and how to change a text or add a language. The guide for
translators (the file format, step by step): [Squirrel!/translations/README.md](../../../Squirrel!/translations/README.md).

## 1. In the code

Every text is English in the code, wrapped in `_()` where it is drawn:

```python
from i18n import _
Lcd.drawString(_("Saved"), 5, 5)
renderer.render_options(_("Synced %d of %d") % (done, total))    # translate the pattern, then fill it in
```

- **Data stays English** in its own files - the menus (`menu_tree.py`), the settings, their help and choices
  (`appconfig_schema.py`), block names (`intervals.py`), weekday names - and is translated where it is drawn. A
  setting's value in `config.txt` never changes with the language.
- **Text built elsewhere in English** (the Bluetooth status lines of `ble/central.py`, which runs without a screen) is
  translated by its pattern: `i18n.fill(text, TEMPLATES)` finds which `%s` / `%d` template the text came from,
  translates the template and fills in the same values; `fill(text, TEMPLATES, INNER)` translates the values too
  (the reason in "failed: %s").
- **Not translated, on purpose:** the text under the clock (the device's motto: *no need to go nuts*, *Squirrel! is
  watching*), the names of the languages (each in its own language, so it can be found whatever the screen speaks),
  log lines and `config.txt` comments.
- **Padding:** MicroPython has no `str.ljust`, and its `"%-10s"` counts bytes, so a label with ą or é comes out short.
  Columns use `charmap.pad(text, width)`.

## 2. At run time

`lang/<code>.py` holds `T = (english, translated, english, translated, ...)` sorted by the English text; `_()` finds
a text by binary search. Frozen into the firmware, the tuple stays in flash: a language costs next to no RAM (under
1 KB on the Cardputer). A text with no translation is shown in English.

- `_()` keeps the last 200 texts it looked up (a screen draws the same ones again): 91 µs per text on the watch
  instead of 763 µs, rendering about 2 % slower than in English.
- The language follows the setting `LANGUAGE` through `cfg.on_change`; `_()` itself reads nothing.
- Any language but English turns the font on (`squirrel_app._language_font`). On the Cardputer that is
  `squirrel.vlw`; the watches' 6 × 8 font has the accented letters of the four languages built in
  (`drivers/glcdfont_latin.py`, generated by `tools/fonts/make_latin_glyphs.py`). Letters a display cannot draw are
  folded to plain ones (`charmap.fold`: ą → a).
- **Your own texts on the device:** `<BASE_DIR>/lang_<code>.tsv` (`/Squirrel/lang_pl.tsv` - on the Cardputer's SD
  card), in the format of `translations/<code>.tsv`, with only the lines you want different. They win over the table
  (`lang_en.tsv` changes the English texts too), are read when the language is chosen, and are the only texts kept
  in RAM.

## 3. The files

```
translations/<code>.tsv     the translations: "en<TAB><code>", then "English<TAB>translation" lines (\n = line break)
translations/README.md      the guide for translators
lang/<code>.py              GENERATED from translations/<code>.tsv - frozen into the firmware
tools/i18n/build.py         translations/*.tsv -> lang/*.py
tools/i18n/check.py         every text translated? placeholders the same? labels short enough? (exit 1 if not)
tools/i18n/texts.py         where the texts are: _() calls in the code, plus the data (menus, settings, names)
tools/i18n/unwrapped.py     string literals that look like UI text but have no _() (a list to read, not to trust)
tools/i18n/wrap.py          puts _() around the texts a file draws (review the diff)
```

```bash
python3 tools/i18n/check.py              # summary
python3 tools/i18n/check.py --missing    # the missing texts, with where they are used
python3 tools/i18n/check.py --add        # add them to every translations/*.tsv, to be translated
python3 tools/i18n/build.py              # then the tables for the firmware
```

`check.py` also stops a translation whose `%s` / `%d` differ from the English one, and a setting label over 18
characters (Personalize shows a label and its value on one row).

## 4. A new language

1. Copy a file to `translations/<code>.tsv`, change the first line to `en<TAB><code>`, translate the second column.
2. Add the code to `LANGUAGES` in `i18n.py`, to the choices of `LANGUAGE` in `appconfig_schema.py`, and its own name to
   `_NATIVE_NAMES` in `screens/personalize_screen.py`.
3. Letters the watches' font lacks: add them to `LETTERS` in `tools/fonts/make_latin_glyphs.py` (a base letter and a
   mark) or draw them in `DRAWN`, then `--write`; the Cardputer's `squirrel.vlw` has all of Latin-1 and Latin
   Extended-A.
4. `check.py`, `build.py`, a build; screenshots of every screen (`tools/sim/shots_scenario.py`, with sample content in
   the language added to its `SAMPLES`; `tools/hwtest/twatch_screens.py --lang <code>`) - and read them as a user:
   does every text fit, does it sound right?

## 5. Writing the texts

- Short: a Cardputer row has 38-40 characters, a setting label 18; a watch row at size 2 has 20.
- One word for one thing everywhere (*routine*, *To-Do*, *the squirrel* - the device the others wait for); the same
  register throughout - plain, calm, never scolding.
- No grammatical agreement with a value filled in (a block name, a device name): *Potem: %s*, not *Następny: %s*,
  since the block may be *Przerwa* or *Odpoczynek*.
- Two-letter weekday names in pickers (*Pn Wt Śr*): single letters are ambiguous in several languages.
