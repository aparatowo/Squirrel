# Sprachen

*[English](../en/i18n.md) · [Polski](../pl/i18n.md) · [Français](../fr/i18n.md) · Deutsch*

Wie Squirrel! Englisch, Polnisch, Französisch und Deutsch spricht, und wie man einen Text ändert oder eine Sprache
hinzufügt. Die Anleitung für Übersetzer (das Dateiformat, Schritt für Schritt):
[Squirrel!/translations/README.md](../../../Squirrel!/translations/README.md).

## 1. Im Code

Jeder Text ist im Code englisch, dort, wo er gezeichnet wird, in `_()` gefasst:

```python
from i18n import _
Lcd.drawString(_("Saved"), 5, 5)
renderer.render_options(_("Synced %d of %d") % (done, total))    # translate the pattern, then fill it in
```

- **Daten bleiben englisch** in ihren eigenen Dateien - die Menüs (`menu_tree.py`), die Einstellungen, ihre Hilfe und
  Auswahlen (`appconfig_schema.py`), Blocknamen (`intervals.py`), Wochentagsnamen - und werden dort übersetzt, wo sie
  gezeichnet werden. Der Wert einer Einstellung in `config.txt` ändert sich nie mit der Sprache.
- **Text, der anderswo auf Englisch gebaut wird** (die Bluetooth-Statuszeilen aus `ble/central.py`, das ohne
  Bildschirm läuft), wird über sein Muster übersetzt: `i18n.fill(text, TEMPLATES)` findet, aus welcher `%s` /
  `%d`-Vorlage der Text kam, übersetzt die Vorlage und setzt dieselben Werte ein; `fill(text, TEMPLATES, INNER)`
  übersetzt auch die Werte (den Grund in "failed: %s").
- **Absichtlich nicht übersetzt:** der Text unter der Uhr (das Motto des Geräts: *no need to go nuts*, *Squirrel! is
  watching*), die Namen der Sprachen (jeder in seiner Sprache, damit man ihn findet, egal was der Bildschirm spricht),
  Protokollzeilen und die Kommentare in `config.txt`.
- **Auffüllen:** MicroPython hat kein `str.ljust`, und sein `"%-10s"` zählt Bytes, also wird eine Beschriftung mit ą
  oder é zu kurz. Spalten benutzen `charmap.pad(text, width)`.

## 2. Zur Laufzeit

`lang/<code>.py` enthält `T = (english, translated, english, translated, ...)`, sortiert nach dem englischen Text;
`_()` findet einen Text durch binäre Suche. In die Firmware eingefroren bleibt das Tupel im Flash: eine Sprache kostet
fast kein RAM (unter 1 KB auf dem Cardputer). Ein Text ohne Übersetzung wird auf Englisch gezeigt.

- `_()` merkt sich die letzten 200 gesuchten Texte (ein Bildschirm zeichnet dieselben wieder): 91 µs pro Text auf der
  Uhr statt 763 µs, das Zeichnen etwa 2 % langsamer als auf Englisch.
- Die Sprache folgt der Einstellung `LANGUAGE` über `cfg.on_change`; `_()` selbst liest nichts.
- Jede Sprache außer Englisch schaltet die Schrift ein (`squirrel_app._language_font`). Auf dem Cardputer ist das
  `squirrel.vlw`; die 6 × 8-Schrift der Uhren hat die Akzentbuchstaben der vier Sprachen eingebaut
  (`drivers/glcdfont_latin.py`, erzeugt von `tools/fonts/make_latin_glyphs.py`). Buchstaben, die ein Display nicht
  zeichnen kann, werden vereinfacht (`charmap.fold`: ą → a).
- **Eigene Texte auf dem Gerät:** `<BASE_DIR>/lang_<code>.tsv` (`/Squirrel/lang_de.tsv` - auf der SD-Karte des
  Cardputers), im Format von `translations/<code>.tsv`, nur mit den Zeilen, die anders sein sollen. Sie gewinnen gegen
  die Tabelle (`lang_en.tsv` ändert auch die englischen Texte), werden gelesen, wenn die Sprache gewählt wird, und sind
  die einzigen Texte im RAM.

## 3. Die Dateien

```
translations/<code>.tsv     the translations: "en<TAB><code>", then "English<TAB>translation" lines (\n = line break)
translations/README.md      the guide for translators
lang/<code>.py              GENERATED from translations/<code>.tsv - frozen into the firmware
tools/i18n/build.py         translations/*.tsv -> lang/*.py
tools/i18n/check.py         every text translated? placeholders the same? labels short enough? (exit 1 if not)
tools/i18n/texts.py         where the texts are: _() calls in the code, plus the data (menus, settings, names)
tools/i18n/unwrapped.py     string literals that look like UI text but have no _() (a list to read, not to trust)
tools/i18n/wrap.py          puts _() around the texts a file draws (review the diff)
```

```bash
python3 tools/i18n/check.py              # summary
python3 tools/i18n/check.py --missing    # the missing texts, with where they are used
python3 tools/i18n/check.py --add        # add them to every translations/*.tsv, to be translated
python3 tools/i18n/build.py              # then the tables for the firmware
```

`check.py` stoppt auch eine Übersetzung, deren `%s` / `%d` sich vom Englischen unterscheiden, und eine
Einstellungsbeschriftung über 18 Zeichen (Anpassen zeigt eine Beschriftung und ihren Wert in einer Zeile).

## 4. Eine neue Sprache

1. Kopiere eine Datei nach `translations/<code>.tsv`, ändere die erste Zeile in `en<TAB><code>`, übersetze die zweite
   Spalte.
2. Füge den Code zu `LANGUAGES` in `i18n.py` hinzu, zu den Auswahlen von `LANGUAGE` in `appconfig_schema.py`, und
   seinen eigenen Namen zu `_NATIVE_NAMES` in `screens/personalize_screen.py`.
3. Buchstaben, die der Schrift der Uhren fehlen: füge sie zu `LETTERS` in `tools/fonts/make_latin_glyphs.py` hinzu (ein
   Grundbuchstabe und ein Zeichen) oder zeichne sie in `DRAWN`, dann `--write`; die `squirrel.vlw` des Cardputers hat
   ganz Latin-1 und Latin Extended-A.
4. `check.py`, `build.py`, ein Build; Screenshots jedes Bildschirms (`tools/sim/shots_scenario.py`, mit Beispielinhalt
   in der Sprache in seinen `SAMPLES`; `tools/hwtest/twatch_screens.py --lang <code>`) - und lies sie als Nutzer: passt
   jeder Text, klingt er richtig?

## 5. Die Texte schreiben

- Kurz: eine Zeile des Cardputers hat 38-40 Zeichen, eine Einstellungsbeschriftung 18; eine Zeile der Uhr in Größe 2
  hat 20.
- Ein Wort für eine Sache überall (*Routine*, *Aufgabe*, *das Eichhörnchen* - das Gerät, auf das die anderen warten);
  derselbe Ton überall - schlicht, ruhig, nie tadelnd.
- Keine grammatische Übereinstimmung mit einem eingesetzten Wert (einem Blocknamen, einem Gerätenamen): *Danach: %s*,
  nicht *Nächster: %s*, denn der Block kann *die Pause* oder *das Vorbereiten* sein.
- Zweibuchstabige Wochentagsnamen in Auswahlen (*Mo Di Mi*): einzelne Buchstaben sind in mehreren Sprachen
  mehrdeutig.
